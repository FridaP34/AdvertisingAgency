# גיבוי מסד הנתונים

## מה קיים היום

תוכנית Supabase Free **אינה כוללת גיבויים אוטומטיים**. אם עבודה נמחקת בטעות,
ב־Storage או במסד — היא איננה ניתנת לשחזור משרת Supabase.

## מה כן מגן עליך

- **הסתרה במקום מחיקה** — סימון עבודה כ"מוסתרת" (`setWorkPublished`) משאיר
  אותה ואת קבציה במקומם, והיא רק יורדת מהאתר. זו הפעולה הבטוחה כשמהססים.
- **מחיקה היא בלתי הפיכה** — `deleteWork` מוחק את השורה, את שורות הקבצים
  ואת הקבצים עצמם מ־Storage. אין דרך חזרה.
- **שמירה נוגעת רק בעבודה שנערכה** — שאר העבודות נשארות כפי שהן.

## גיבוי ידני (מומלץ לפני כל שינוי גדול)

ב־Supabase → **Database** → **Backups** ניתן להוריד גיבוי אם התוכנית כוללת.
ב־Free אפשר להוריד את הנתונים דרך ה־SQL Editor:

```sql
-- רשימת העבודות וכל הקבצים שלהן, כטקסט שאפשר לשמור
select jsonb_pretty(jsonb_build_object(
  'works', (select jsonb_agg(w order by w->>'slug') from public.works w),
  'assets', (select jsonb_agg(a) from public.works_assets a),
  'version', public.works_version()
));
```

שומרים את הפלט כקובץ `.json` במחשב (או בכונן גיבוי), וכך אפשר לשחזר את
הנתונים אם משהו נמחק.

## שחזור

1. מריצים מחדש את `supabase/schema.sql` (בטוח להריץ על מסד קיים).
2. מעלים את הקבצים בחזרה ל־Storage תחת `works/` באותם נתיבים שהיו ב־`url`.
3. מריצים `insert into public.works ...` מתוך ה־JSON שנשמר.

## שדרוג אפשרי

תוכנית Pro של Supabase כוללת גיבויים יומיים אוטומטיים. אם האתר הופך לתיק
העבודות העיקרי של העסק, שווה לשקול אותה.
